小怪营地 v1.1.0｜不用懂代码的使用与更新指南

1. 这次先用起来

安装包：01_安装包\v1.1.0\MonsterCamp-Setup-1.1.0-x64.exe
双击后按向导操作；如果已经安装旧版，先按第 3 节备份、退出旧版再安装。
适用于 Windows 64 位。发给朋友，只发 EXE 即可。
本地生成的安装包未签名；遇到无法判断的系统提示，把具体提示交给 JoyCode。

点击桌面边缘的小怪，写下一件事情，选择难度，再按回车记录。
不选择难度时默认为轻松。Shift + 回车可换行。

轻松：小体型，10 金币，例如回复消息、确认时间。
普通：中体型，20 金币，例如整理资料、完成常规表格。
挑战：大体型，40 金币，例如完成复杂方案。
这些只是判断难度的例子，你可以根据实际投入自己选择。

12 种外形自动分配，同一种外形也有三种体型。
任务保存后，修改文字、日期或难度不会改变它的外形。
点击任务文字可以编辑。已完成任务如需改难度，先在已完成列表撤销完成。

完成时按对应档位获得金币；撤销时扣回实际所得金币。
再次完成按当时选择的难度结算；重复点击同一任务不会重复奖励。
删除已完成记录会保留金币和营地进度。
帐篷、篝火、小屋、花园的解锁门槛仍是 30、100、250、500 金币。

2. 三样东西分别保存什么？

安装包：做好的软件。改源码不会自动更新已安装的软件。
项目源码：软件的原材料。固定在 02_项目源码 中维护。
个人数据：你的待办、金币、营地和设置。保存在另一个应用数据目录里。

程序离线使用，各人的数据在各自电脑里，不会互相同步。
只备份本项目文件夹，不能备份你使用中产生的记录。

3. 从 v1.0.0 升到 v1.1.0

① 打开旧版小怪营地，进入设置，展开「查看数据保存位置」。
② 记下或复制显示的准确路径，在文件资源管理器中打开。
③ 从电脑右下角托盘图标菜单选择「退出（暂停提醒）」。
   只是关闭或收起面板不算退出。
④ 把刚才显示的整个数据文件夹复制到你自己保管的位置。
   例如：文档\小怪营地数据备份\升级前-v1.0.0-日期。
   核对备份中有 camp.json；已有 camp.backup.json 时也一起保留。
⑤ 双击新版安装包，沿用原安装位置；通常不需要先卸载旧版。
⑥ 新版第一次打开旧记录时会自动先备份，再升级数据格式。
   旧任务保持原外形，默认轻松；原金币、已完成记录和营地进度保留。
⑦ 进入设置确认版本显示 1.1.0，再试一下新增、完成和撤销任务。

本次在独立数据目录验证了旧记录迁移，以及打包程序的运行。
当前机器没有可用 Windows Sandbox，未执行真实安装向导和覆盖安装测试。
安装或打开遇到问题时，保留备份并把提示交给 JoyCode，不要清空数据重试。

4. 自动保存的升级前副本在哪里？

设置里显示的保存位置以 data 文件夹结尾。
在文件资源管理器中进入它的上一级，打开 backups 文件夹。
其中「pre-v1.1.0-时间戳-随机后缀」就是本次自动保存的原始数据副本。

副本包含当时的 camp.json、已有的 camp.backup.json，以及 SHA256.json 校验记录。
它不会被日常自动备份覆盖，也不会进入分享给别人的安装包。
只有实际存在旧数据且发生迁移时才会创建；新装空营地不会创建迁移备份。
升级备份或写入失败时，程序会停止并保留原记录，不会用空营地覆盖。

你自己的手动备份仍建议保留。
camp.backup.json 只代表前一次有效保存，不等同于长期备份。

5. 如果需要回到 v1.0.0

新版数据格式已经改变，不能只装回旧版并指望直接读取新数据。
先让 JoyCode 保存当前数据现场，确认要用哪份升级前副本。
软件退出后，保留当前 data 文件夹的副本，再恢复相应的旧数据，
随后使用 01_安装包\v1.0.0 中的安装包。
恢复升级前副本会失去升级后新增的修改；当前数据副本要单独保管。

不确定时，可以直接说：
“我从 v1.0.0 升级到了 v1.1.0，现在出现……。
请先保留当前数据和升级前副本，检查能否修复；需要回退时请说明会影响哪些记录。”

6. 后续继续迭代，你只需要做这几步

提出需求 → 备份 → JoyCode 修改和打包 → 安装试用 → 确认。

填写「下一版需求.txt」，或直接告诉 JoyCode 想改什么、举一个例子。
一次先改一到三件明确的事。

可以复制这段话：
“请在小怪营地-待办项目的 02_项目源码 中继续迭代。
本次需求是：【填写】。
请先阅读使用与更新说明，核对当前版本并备份源码，保留旧安装包。
修改后验证原有功能及旧数据兼容性，更新版本号并生成新版 Windows 安装包。
测试用独立数据，验收后的成品放入 01_安装包 对应版本目录。
更新说明、截图和校验清单，最后告诉我该双击哪个文件，以及如何保留原来的数据。”

你的试用清单：
□ 旧任务、已完成记录、金币、营地进度还在。
□ 新增、编辑、搜索、提醒和桌面浮标正常。
□ 新需求按照预期生效。
□ 退出后重新打开，数据仍然正确。
□ 设置里的版本号与安装的新版一致。

7. 以后怎么命名和整理？

最外层继续叫「小怪营地-待办项目」，不需要每次重新改名。
当前源码固定在 02_项目源码。
已发布安装包、截图分别放进对应的 v版本号 文件夹。
源码备份带原版本号和日期时间，例如「源码与说明-v1.1.0-升级前-日期时间.zip」。
小修复可以用 1.1.1，下一批新功能可以用 1.2.0；这些只是未来编号示例。

不要只改 EXE 文件名来当作新版本；让 JoyCode 同步程序中的版本信息。
普通使用只需要安装包。对外分享完整源码时，应排除 node_modules、dist、output，
并确保没有夹带真实个人数据；这部分交给 JoyCode 处理即可。
