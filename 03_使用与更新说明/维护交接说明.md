## 本项目已有命令

原交付验证环境为 Node.js 24.19.0；依赖版本以 package-lock.json 为准。安装现有 EXE 无需这些开发步骤。

```powershell
npm ci
node scripts/prepare-fonts.cjs
npm test
npm run test:desktop
npm run test:upgrade
npm run dist
```

首次恢复开发依赖需要联网；字体已在交付源码内，prepare-fonts 用于从锁定的依赖重新准备字体。若缺少 Electron 运行时，按 README 的说明处理。执行外部命令后检查退出码，失败时停止后续打包或交付步骤。

需要开发预览时可运行 `npm start`，但普通启动会按实际应用的数据目录运行；处理用户项目时先安排数据备份，优先使用项目已有的测试模式与独立数据路径进行验证。不要直接用真实用户数据试验修改。

桌面自动化 `scripts/smoke.cjs` 会自行设置 `CAMP_TEST_DATA`、传入 `--test-mode`，将测试数据存放于 `output/desktop-test-*`。构建后可在独立 PowerShell 会话中验证打包程序：

```powershell
$env:CAMP_EXECUTABLE = (Resolve-Path -LiteralPath '.\dist\win-unpacked\MonsterCamp.exe').Path
npm run test:desktop
npm run test:upgrade
```

关闭该会话后环境设置即结束。测试中使用的是解包后的应用程序，不能将 Setup 安装器作为 CAMP_EXECUTABLE。

## 每次迭代与发布

1. 读取用户需求、当前源码与更新记录；先备份当前源码。备份无需包含 node_modules、dist、output 等可重建文件，也不要包含真实用户数据。
2. 修改功能，按影响范围运行测试。发布前跑核心测试、桌面测试和打包程序测试，人工验收安装、原版本升级及用户指定行为。无法执行的检查明确记录为未验证。
3. 发布版本号需要同步 `package.json`、`package-lock.json` 的根版本与 `packages[""]` 版本、`src/index.html` 设置面板中的显示版本，以及相应说明。不要批量替换锁文件中第三方依赖的版本。
4. 保持应用身份一致：`build.appId=io.monstercamp.desktop`、`productName=小怪营地`、`executableName=MonsterCamp`，并注意 `src/main.cjs` 的 `app.setName` 与 `app.setAppUserModelId`。改变身份或数据路径需要专门迁移方案。
5. `src/domain.js` 的 `validateState` 只接受格式 2，`migrateState` 校验格式 1 后转换。难度为 `easy / normal / hard`，未完成任务 `rewardEarned=0`，完成时记录对应的 10/20/40，已完成难度不可直接修改。`coinsDelta` 由主进程结算，界面不传入奖励金额。软件版本号与数据格式号分开维护。
6. 数据实际存储在 `app.getPath('userData')/data`；设置页显示 `store.directory`。升级前备份该目录，并用其隔离副本做兼容检查，记录升级后的待办、金币、营地进度与设置是否保留。卸载配置 `deleteAppDataOnUninstall=false` 不等同于升级兼容性已经通过。
7. 构建成功后检验安装包，保留旧版；将确认可交付的 EXE、该版校验值与说明放入 `01_安装包/v版本号/`。更新「版本更新记录.txt」并区分自动测试、人工验证和未验证项目。
8. 需要交付完整项目时，排除真实用户数据和 `02_项目源码/node_modules`、`dist`、`output` 开发缓存。根目录文件校验清单的键相对于交付根目录，排除清单自身及上述三类目录。日常源码变更会使校验值失效，应在下次交付时重建；原始历史清单不改写。

迁移备份由 Store 在读取旧主文件或恢复旧备用文件时创建，位置为数据目录上一级的 `backups/pre-v1.1.0-时间戳-随机后缀/`。保存原始字节并核对后才写格式 2，不能在备份失败时继续迁移。这些数据属于用户个人记录，不能拷入源码发布包。

本机没有可用 Windows Sandbox，本版未执行真实 NSIS 安装向导或覆盖安装。验证过的范围是隔离数据迁移、开发程序和打包程序桌面流程；后续不得把这些结果直接写成安装升级通过。

## 回退

回退前先保存失败现场及最新数据副本。只有确认数据格式兼容时才直接换回旧程序；否则同时恢复相应版本的数据备份，并向用户说明备份之后的更改可能丢失。原始 ZIP 解压到单独目录确认后再取用，不直接覆盖正在工作的源码。
