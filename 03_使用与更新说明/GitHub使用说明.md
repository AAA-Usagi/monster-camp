# 小怪营地的 GitHub 保存与更新

目标账号：`AAA-Usagi`。拟用仓库名称：`monster-camp`，首次按私有仓库准备。是否已上传以实际 GitHub 仓库和发布记录为准；本地 Git 提交不等于上传成功。

## 三个常用词

- Commit（提交）：把当前修改保存为本地历史记录。
- Push（上传）：把已提交的修改保存到 GitHub。
- Release（版本发布）：为一个经过测试的版本附上安装包、校验文件和更新说明。

第一次连接账号，需要你在 GitHub 官方登录页面完成登录授权。密码、验证码和访问令牌都不需要发给 JoyCode。

## 以后继续修改

继续使用当前「小怪营地-待办项目」文件夹。代码仍只在 `02_项目源码` 维护，无需另建一份 GitHub 源码。

你可以直接说：

> 请继续迭代小怪营地，本次需求是……。先核对本地与 GitHub 状态并备份，用独立数据完成开发和验证。然后保存本地提交并上传 GitHub；生成新版安装包、说明和截图，按版本发布到 Releases，保留旧版本。

有多台电脑时，每次修改前先同步 GitHub；发现冲突时交给 JoyCode 处理，不要强制覆盖。

## 上传范围

仓库保存源码、使用说明、测试结果和示例截图。安装包单独作为 Releases 附件。`01_安装包`、`05_历史备份`、源码中的 `node_modules`、`dist`、`output` 留在本机。根目录文件校验清单属于完整本地交付，也不进入源码仓库。

项目设置了忽略规则，避免普通提交带上本地数据、密钥、依赖和缓存。每次发布前仍需检查实际上传清单。

GitHub 保存的是软件项目，不能代替个人待办备份。个人待办的位置和备份方法见[使用与更新指南](使用与更新指南.txt)。

## 维护者注意

Git 仓库根目录为「小怪营地-待办项目」，默认分支为 `main`。npm 命令仍从 `02_项目源码` 执行。首次提交对应已验证的 v1.1.0；没有伪造更早版本的提交历史。

保留现有安装身份和数据目录。发布前检查软件版本、安装包 SHA-256、测试结果与实际提交一致；同一发布版本不覆盖既有附件。变更可见性或强制改写远端历史需先与用户确认。

本地生成交付校验清单时，还需排除 `.git/`，除此以外继续排除源码中的 `node_modules/`、`dist/`、`output/` 与清单自身。
